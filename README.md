# speedmeter

Консольный измеритель скорости интернета. Скрипт скачивает файл по указанному
адресу (лучше всего подходит тяжёлая картинка) 10 раз подряд, дожидается каждого
ответа целиком и печатает среднее время запроса, объём скачанных данных и
скорость.

## Требования

Нужен только [uv](https://docs.astral.sh/uv/getting-started/installation/).
Нужную версию Python (3.12+) и зависимости он поставит сам.

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# или: brew install uv
```

## Запуск

```bash
git clone https://github.com/achervontsev/speedtest.git
cd speedtest
uv run speedmeter https://upload.wikimedia.org/wikipedia/commons/f/ff/Pizigani_1367_Chart_10MB.jpg
```

При первом запуске `uv run` создаст виртуальное окружение и установит
зависимости.

Можно запустить и без клонирования:

```bash
uvx --from git+https://github.com/achervontsev/speedtest speedmeter <URL>
```

### Параметры

| Аргумент           | Переменная окружения  | Описание                                   | По умолчанию |
|--------------------|-----------------------|--------------------------------------------|--------------|
| `URL`              | `SPEEDMETER_URL`      | адрес файла для скачивания, http или https | обязателен   |
| `-n`, `--requests` | `SPEEDMETER_REQUESTS` | сколько запросов сделать подряд            | `10`         |
| `-t`, `--timeout`  | `SPEEDMETER_TIMEOUT`  | таймаут на подключение и каждое чтение, с  | `30`         |
| `--version`        |                       | показать версию                            |              |
| `-h`, `--help`     |                       | справка                                    |              |

Таймаут ограничивает не всё скачивание, а каждую сетевую операцию по
отдельности: установку соединения и ожидание очередного куска данных. Большой
файл может качаться дольше 30 секунд, если данные идут без пауз. Ошибка
будет, только если сервер замолчит дольше таймаута.

### Настройка через `.env`

Параметры можно не передавать каждый раз в командной строке, а один раз
записать в файл `.env`:

```bash
cp .env.example .env   # поправьте значения под себя
uv run speedmeter      # URL и остальное возьмутся из .env
```

`.env` ищется в текущей директории и в git не попадает. Если параметр задан в
нескольких местах, побеждает источник выше по списку:

1. аргумент командной строки;
2. переменная окружения, например `SPEEDMETER_REQUESTS=3 uv run speedmeter`;
3. файл `.env`;
4. значение по умолчанию.

Все значения проверяются при запуске. Если что-то не так (URL не http(s),
отрицательный таймаут, опечатка в имени переменной в `.env`), скрипт сразу
сообщит, в чём проблема.

Если запрос завершился ошибкой (HTTP 4xx/5xx, нет сети, таймаут), скрипт
пишет причину в stderr и выходит с кодом `1`.

## Как считается результат

- Запросы идут строго последовательно: следующий начинается только после того,
  как предыдущий файл скачан полностью.
- Время запроса считается от отправки запроса до получения последнего байта
  тела.
- Тело читается потоком и сразу отбрасывается, поэтому даже большие файлы не
  занимают память. Считаются байты, которые реально пришли по сети, то есть
  до распаковки gzip и других кодировок.
- **Скорость = весь скачанный объём / всё время.** Среднее арифметическое
  скоростей отдельных запросов сюда не подходит: оно завышает результат за счёт
  быстрых запросов.
- Единицы десятичные, как у провайдеров: 1 MB = 1 000 000 байт. Скорость
  выводится в мегабайтах (MB/s) и в мегабитах (Mbit/s). В мегабитах указывают
  скорость тарифа.
- Все запросы идут через одно соединение (keep-alive), поэтому DNS, TCP и TLS
  приходятся только на первый запрос. Обычно он заметно медленнее остальных.
- Редиректы отрабатываются автоматически.

Чем больше файл, тем точнее результат: на маленьких файлах основную часть
времени занимают задержки сети, а не сама передача данных. Лучше брать файлы
от 10 MB. Учтите, что результат зависит и от сервера: скорость не может быть
выше той, с которой он отдаёт файл.

## Разработка

```bash
uv sync                            # окружение со всеми dev-зависимостями
uv run pre-commit install          # проверки перед каждым коммитом
uv run pytest                      # тесты
uv run pre-commit run --all-files  # все проверки вручную
```

Инструменты:

- [ruff](https://docs.astral.sh/ruff/): линтер и форматтер;
- [mypy](https://mypy.readthedocs.io/) в режиме `--strict`;
- [pytest](https://docs.pytest.org/) и `pytest-asyncio`. Сеть в тестах
  подменяется через `httpx.MockTransport`, так что интернет для них не нужен;
- [pre-commit](https://pre-commit.com/). Ruff и mypy запускаются через
  `uv run`, поэтому их версии берутся из `uv.lock` и везде одинаковые;
- GitHub Actions прогоняет pre-commit и тесты на каждый push и pull request.

### Структура проекта

```text
src/speedmeter/
├── config.py    # константы и настройки: аргументы, переменные окружения, .env
├── cli.py       # разбор аргументов, цикл запросов, вывод в консоль
├── meter.py     # скачивание файла и замер времени (httpx.AsyncClient)
├── stats.py     # агрегация замеров: объём, среднее время, скорость
└── __main__.py  # запуск через python -m speedmeter
tests/           # тесты для каждого модуля
```

### Почему так

- **Асинхронный клиент при последовательных запросах.** По условию запросы идут
  один за другим, но с асинхронным API замер легко расширить. Например,
  параллельные загрузки через `asyncio.TaskGroup` добавляются без переписывания
  сетевого кода.
- **Настройки через `pydantic-settings`.** Одна типизированная модель
  `Settings` читает аргументы, переменные окружения и `.env` и сама
  проверяет значения. Самописный разбор и валидация не нужны.
- **Пакет называется `speedmeter`, а не `speedtest`.** Имя `speedtest` уже
  занимает модуль популярного пакета `speedtest-cli`, и при установке обоих
  они бы конфликтовали.
- **Тесты.** Проект маленький, но в нём есть логика, которую легко сломать
  незаметно: формула скорости, подсчёт байт, валидация аргументов, обработка
  ошибок. Тесты на это короткие и работают без сети.
